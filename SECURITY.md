# Security Policy

## Supported Versions

Only the latest major/minor releases receive security patches. Please upgrade to a supported version before reporting a security issue.

| Version | Supported          | Security Maintenance End |
| ------- | ------------------ | ------------------------ |
| 2.x.x   | :white_check_mark: | Active                   |
| 1.x.x   | :x:                | Ended Dec 2025           |
| < 1.0   | :x:                | Deprecated               |

## Reporting a Vulnerability

We take the security of this project seriously. If you believe you have found a security vulnerability, please follow these steps:

### How to Submit
* **Do NOT report security vulnerabilities through public GitHub issues.**
* Submit private reports directly via **[GitHub Private Vulnerability Reporting]**(https://github.com/YOUR-ORG/YOUR-REPO/security/advisories/new) *(recommended)*.
* Alternatively, email details to **security@yourdomain.com**. Encrypt sensitive information using our PGP key `[Key ID/Link]` if available.

### What to Include
To help us triage the issue quickly, include:
* Description of the vulnerability and its potential impact.
* Step-by-step instructions or proof-of-concept (PoC) code to reproduce it.
* Any affected dependencies or environments.

### Response & Timeline
* **Initial Acknowledgment:** Within **48 hours**.
* **Status Update / Triage:** Within **5 business days** with an assessment or mitigation plan.
* **Fix & Release Target:** Critical issues within **14 days**; high/medium issues within **30 days**.

### Disclosure Policy
We follow coordinated vulnerability disclosure. Please allow us time to release a patch before publicly sharing details. We credit security researchers in our release notes unless anonymity is requested.
